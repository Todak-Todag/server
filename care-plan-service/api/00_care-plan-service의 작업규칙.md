# server/care-plan-service 작업 규칙

- 관련 파일을 읽고 분석하는 것은 자유롭게 해도 된다.
- 코드 수정이 필요하다고 판단되면 먼저 수정 대상 파일과 수정 이유를 설명한다.
- 사용자의 명시적인 허락 없이 기존 코드 파일을 수정하지 않는다.
- 사용자의 명시적인 허락 없이 새 코드 파일을 생성하지 않는다.
- 사용자의 명시적인 허락 없이 파일을 삭제하지 않는다.
- 사용자의 명시적인 허락 없이 테스트 코드도 작성하지 않는다.
- 사용자의 명시적인 허락 없이 터미널 명령으로 코드베이스를 변경하지 않는다.
- `git add`, `git commit`, `git push`, `git reset`, `git checkout`, `git restore` 등 Git 변경 명령은 절대 금한다.
- 사용자가 "구현해", "수정해", "적용해", "작성해", "진행해" 등 명확한 실행 의사를 표현하기 전까지는 읽기와 분석만 수행한다.

## 기본 작업 방식

1. 요구사항 문서를 읽는다.
2. 관련 코드를 탐색한다.
3. 현재 구조와 흐름을 설명한다.
4. 수정이 필요한 파일 목록과 이유를 제시한다.
5. 구현 방안을 제안한다.
6. 사용자의 명시적인 승인을 기다린다.
7. 승인받은 범위만 수정한다.

## 작업 범위

- 이 작업의 소유 범위는 `server/care-plan-service`이다.
- `care-plan-service` 외부의 다른 마이크로서비스 코드는 수정하지 않는다.
- 다른 서비스의 코드는 필요한 경우 참조 목적으로 읽을 수만 있다.
