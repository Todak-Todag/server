# 07. 서비스 수행 결과 등록

| 항목 | 내용 |
| --- | --- |
| Method | `POST` |
| URL | `/api/v1/service-results/{serviceScheduleId}` |
| 사용자 | 서비스 제공자 |
| 카테고리 | 등록 |
| 테이블명 | `p_care_plan_service_results` |

## 설명

서비스 제공자가 담당한 서비스의 수행 결과(실제 시작·종료 일시, 비고)를 등록한다.

## 비즈니스 규칙

- 요청자의 `userId`와 `role`은 `@AuthenticationPrincipal UserContext user`를 통해 확인하며, 해당 서비스 일정에 배정된 서비스 제공자 본인인지와 서비스 제공자 권한을 검증한다.
- 본인이 해당 서비스 일정에 배정된 서비스 제공자인지 검증하기 위해 **provider-service Internal API**(`GET /internal/v1/service-offerings/{serviceOfferingId}`)를 호출하여 해당 `serviceOfferingId`의 `providerId`를 조회하고, 조회된 `providerId`와 요청자의 `userId`를 비교하여 배정 여부를 검증한다 (`schedule-service.md` 5.6절 참고).
- `serviceScheduleId`로 서비스 일정을 조회하여, `status`가 `COMPLETED` 또는 `NO_SHOW`가 아니면 등록에 실패한다(`409 CONFLICT`). 05번(서비스 수행 완료 상태 변경)에서 상태가 먼저 확정된 이후에만 07번(수행 결과 등록)을 진행할 수 있다는 순서 관계가 이로써 확정된다.
- 동일한 `serviceScheduleId`에 대한 중복 등록은 허용하지 않는다 — 하나의 서비스 일정에는 하나의 수행 결과만 등록할 수 있다. 이미 결과가 등록된 상태에서 재등록을 시도하면 `409 CONFLICT`를 반환한다.

## Request

| key | 설명 | value 타입 | 위치 | 제약사항 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- | --- |
| serviceScheduleId | 결과를 등록할 서비스 일정 ID | UUID | Path Variable | - | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| startedAt | 서비스 시작 일시 | LocalDateTime | Body | - | X | `2026-09-01T09:00:00` |
| finishedAt | 서비스 종료 일시 | LocalDateTime | Body | - | X | `2026-09-01T10:00:00` |
| note | 비고 | String | Body | - | O | `정상적으로 서비스 제공 완료` |

## Response

| key | 설명 | value 타입 | 옵션 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- |
| serviceResultId | 생성된 서비스 수행 결과 ID | UUID | - | X | `b2c3d4e5-1234-5678-9abc-def012345678` |

**Example**

```jsx
// 성공
{
  "success": true,
  "code": 201,
  "message": "서비스 수행 결과 등록 성공",
  "data": {
    "serviceResultId": "b2c3d4e5-1234-5678-9abc-def012345678"
  }
}

// 실패
{
  "success": false,
  "code": "AUTH_FORBIDDEN",
  "message": "서비스 수행 결과 등록 실패",
  "details": {
    "reason": "요청 권한이 없습니다."
  },
  "timestamp": "2026-08-27T10:00:00Z"
}
```

## Status

| status | response content |
| --- | --- |
| `201` | 등록 성공 |
| `400` | Validation 실패 |
| `403` | 권한 오류 |
| `404` | 존재하지 않는 서비스 일정 |
| `409` | 서비스 일정의 `status`가 `COMPLETED`/`NO_SHOW`가 아닌 경우, 또는 이미 결과가 등록된 서비스 일정에 재등록을 시도한 경우 |
