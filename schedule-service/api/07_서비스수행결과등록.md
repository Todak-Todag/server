# 07. 서비스 수행 결과 등록

| 항목 | 내용 |
| --- | --- |
| Method | `POST` |
| URL | `/api/v1/service-results/{serviceScheduleId}` |
| 사용자 | 서비스 제공자 |
| 카테고리 | 등록 |
| 테이블명 | `p_care_plan_service_results`, `p_schedule_outbox_events` |

## 설명

서비스 제공자가 담당한 서비스의 수행 결과(실제 시작·종료 일시, 비고)를 등록한다.

## 비즈니스 규칙

- 접근 권한은 `@PreAuthorize("hasRole('SERVICE_PROVIDER')")`로 제한하며, 요청자의 `userId`는 `@AuthenticationPrincipal UserContext user`로 주입받는다.
- 본인이 해당 서비스 일정에 배정된 서비스 제공자인지 검증하기 위해 **provider-service Internal API**(`GET /internal/v1/service-offerings/{serviceOfferingId}`)로 `providerId`를 조회해 요청자 `userId`와 비교한다 (05번과 동일한 메커니즘, `schedule-service.md` 5.6절 참고). 호출은 **DB 트랜잭션 밖**에서 수행한다.
- 대상 일정의 `status`가 **`COMPLETED` 또는 `NO_SHOW`** 가 아니면 `409`(`SERVICE_RESULTS_INVALID_SCHEDULE_STATUS`)로 실패한다. 즉 **05번(서비스 수행 완료 상태 변경)이 반드시 선행**되어야 한다.
- 동일한 `serviceScheduleId`에 대한 중복 등록은 허용하지 않는다 — 하나의 서비스 일정에는 하나의 수행 결과만 등록할 수 있다. 재등록 시 `409`(`SERVICE_RESULTS_ALREADY_EXISTS`).
- `finishedAt`은 `startedAt`보다 뒤여야 한다 (같거나 이르면 `400`).
- **검증 순서**: 배정 제공자 확인(403) → 일정 상태 확인(409) → 중복 등록 확인(409) → 시간 유효성(400).
- **이번 등록으로 케어플랜의 모든 일정이 결말나면 같은 트랜잭션에서 `CarePlanCompleted`가 아웃박스에 적재된다** (11번 문서 참고).

## Request

| key | 설명 | value 타입 | 위치 | 제약사항 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- | --- |
| serviceScheduleId | 결과를 등록할 서비스 일정 ID | UUID | Path Variable | - | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| startedAt | 서비스 시작 일시 | LocalDateTime | Body | `@NotNull` | X | `2026-09-01T09:00:00` |
| finishedAt | 서비스 종료 일시 | LocalDateTime | Body | `@NotNull`, `startedAt`보다 뒤여야 함 | X | `2026-09-01T10:00:00` |
| note | 비고 | String | Body | - | O | `정상적으로 서비스 제공 완료` |

## Response

| key | 설명 | value 타입 | 옵션 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- |
| serviceResultId | 생성된 서비스 수행 결과 ID | UUID | - | X | `b2c3d4e5-1234-5678-9abc-def012345678` |

**Example**

```jsx
// 성공
{
    "success": true,
    "code": 201,
    "message": "서비스 수행 결과 등록 성공",
    "data": {
    "serviceResultId": "b2c3d4e5-1234-5678-9abc-def012345678"
}
}

// 실패
{
    "success": false,
    "code": "SERVICE_RESULTS_ALREADY_EXISTS",
    "message": "이미 결과가 등록된 서비스 일정입니다.",
    "details": {
    "reason": "이미 결과가 등록된 서비스 일정입니다."
},
    "timestamp": "2026-08-27T10:00:00Z"
}
```

## Status

| status | ErrorCode | response content |
| --- | --- | --- |
| `201` | - | 등록 성공 |
| `400` | `INVALID_PARAMETER` | `startedAt`/`finishedAt` 누락·형식 오류, 또는 `finishedAt`이 `startedAt`보다 이르거나 같음 |
| `403` | `AUTH_FORBIDDEN` | 본인이 배정된 서비스 제공자가 아니거나, 존재하지 않는 서비스 일정 (리소스 존재 여부 비노출) |
| `409` | `SERVICE_RESULTS_INVALID_SCHEDULE_STATUS` | 서비스 일정의 `status`가 `COMPLETED`/`NO_SHOW`가 아님 |
| `409` | `SERVICE_RESULTS_ALREADY_EXISTS` | 이미 결과가 등록된 서비스 일정 |
