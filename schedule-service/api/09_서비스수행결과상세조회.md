# 09. 서비스 수행 결과 상세 조회

| 항목 | 내용 |
| --- | --- |
| Method | `GET` |
| URL | `/api/v1/service-results/{serviceResultId}` |
| 사용자 | 퇴원예정자, 서비스 제공자 |
| 카테고리 | 검색 |
| 테이블명 | `p_care_plan_service_results` |

## 설명

퇴원 예정자 또는 서비스 제공자가 특정 서비스 수행 결과 하나의 상세 정보를 조회한다.

## 비즈니스 규칙

- 퇴원 예정자는 **자신이 받은** 서비스 일정의 수행 결과만, 서비스 제공자는 **자신이 제공한** 서비스의 수행 결과만 조회할 수 있다.
- 요청자의 `userId`와 `role`은 `@AuthenticationPrincipal UserContext user`를 통해 확인한다.
- 서비스 제공자가 조회하는 경우 **provider-service Internal API**(`GET /internal/v1/service-offerings/{serviceOfferingId}`)를 호출하여 `providerId`를 조회하고, 요청자 `userId`와 비교해 담당 서비스 제공자인지 검증한다.
- 퇴원 예정자가 조회하는 경우 **care-plan-service Internal API**를 호출하여 `patientId`를 조회하고, 요청자 `userId`와 비교해 담당 환자인지 검증한다.
- 이 API는 **단건 상세 조회**이므로 08번 목록 조회와 달리 "ID 목록을 받아 필터링"하는 방식이 아니라 02/03/04/05번과 같은 **점(point) 검증** 방식을 그대로 쓴다.

> ⚠️ 확인 필요 (신규): 위 두 Internal API는 `p_service_schedules`의 `serviceOfferingId`/`servicePreferenceId`를 기준으로 호출하는데, 이 API는 `p_care_plan_service_results`를 대상으로 하며 이 테이블에는 그 두 컬럼이 없다(`service_schedule_id`만 있음). 따라서 조회된 수행 결과의 `serviceScheduleId`로 `p_service_schedules`를 먼저 조회해 `serviceOfferingId`/`servicePreferenceId`를 얻은 뒤 Internal API를 호출해야 할 것으로 보인다 — 08번 문서에서 지적한 것과 같은 조인 관계가 여기에도 있다. 문서에 명시되어 있지 않아 확인 필요.
>

## Request

| key | 설명 | value 타입 | 위치 | 제약사항 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- | --- |
| serviceResultId | 조회할 수행 결과 ID | UUID | Path Variable | - | X | `b2c3d4e5-1234-5678-9abc-def012345678` |

## Response

| key | 설명 | value 타입 | 옵션 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- |
| serviceResultId | 서비스 수행 결과 ID | UUID | - | X | `b2c3d4e5-1234-5678-9abc-def012345678` |
| serviceScheduleId | 서비스 일정 ID | UUID | - | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| startedAt | 서비스 시작 일시 | LocalDateTime | - | X | `2026-09-01T09:00:00` |
| finishedAt | 서비스 종료 일시 | LocalDateTime | - | X | `2026-09-01T10:00:00` |
| note | 비고 | String | - | O | `null` |

**Example**

```jsx
// 성공
{
  "success": true,
  "code": 200,
  "message": "서비스 수행 결과 상세 조회 성공",
  "data": {
    "serviceResultId": "b2c3d4e5-1234-5678-9abc-def012345678",
    "serviceScheduleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "startedAt": "2026-09-01T09:00:00",
    "finishedAt": "2026-09-01T10:00:00",
    "note": null
  }
}

// 실패
{
  "success": false,
  "code": "SERVICE_RESULTS_NOT_FOUND",
  "message": "서비스 수행 결과 상세 조회 실패",
  "details": {
    "reason": "존재하지 않는 서비스 수행 결과입니다."
  },
  "timestamp": "2026-08-27T10:00:00Z"
}
```

## Status

| status | response content |
| --- | --- |
| `200` | 서비스 수행 결과 상세 조회 성공 |
| `403` | 권한 오류 |
| `404` | 존재하지 않는 서비스 수행 결과 |
