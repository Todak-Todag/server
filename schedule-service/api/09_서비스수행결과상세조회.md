# 09. 서비스 수행 결과 상세 조회

| 항목 | 내용 |
| --- | --- |
| Method | `GET` |
| URL | `/api/v1/service-results/{serviceResultId}` |
| 사용자 | 퇴원예정자, 서비스 제공자 |
| 카테고리 | 검색 |
| 테이블명 | `p_care_plan_service_results` |

## 설명

퇴원 예정자 또는 서비스 제공자가 특정 서비스 수행 결과 하나의 상세 정보를 조회한다.

## 비즈니스 규칙

- 퇴원 예정자는 **자신이 받은** 서비스의 수행 결과만, 서비스 제공자는 **자신이 제공한** 서비스의 수행 결과만 조회할 수 있다.
- 접근 권한은 `@PreAuthorize("hasAnyRole('PATIENT', 'SERVICE_PROVIDER')")`로 제한하며, 요청자의 `userId`/`role`은 `@AuthenticationPrincipal UserContext user`로 주입받는다.
- 이 API는 **단건 상세 조회**이므로 08번 목록 조회와 달리 02/03/04/05번과 같은 **점(point) 검증** 방식을 쓴다.

### ✅ 확정 (2026-09-08): 검증 절차

`p_care_plan_service_results`에는 `service_offering_id`/`service_preference_id`가 없고 `service_schedule_id`만 있으므로, **결과 → 일정 → Internal API** 순서로 조회한다.

1. `serviceResultId`로 수행 결과를 조회한다 (없으면 `403`).
2. 결과의 `serviceScheduleId`로 서비스 일정을 조회해 `servicePreferenceId`/`serviceOfferingId`를 얻는다 (없으면 `403`).
3. 역할에 따라 Internal API로 소유권을 검증한다 (DB 트랜잭션 밖).
   - **퇴원 예정자**: care-plan-service `GET /internal/v1/service-preferences/{servicePreferenceId}/care-plan` → `patientId`와 요청자 `userId` 대조
   - **서비스 제공자**: provider-service `GET /internal/v1/service-offerings/{serviceOfferingId}` → `providerId`와 요청자 `userId` 대조

- 논리 삭제된 결과/일정은 조회 대상이 아니다.
- **존재하지 않는 결과와 남의 결과를 구분하지 않고 모두 `403 AUTH_FORBIDDEN`으로 응답한다** (02번과 동일 정책).

## Request

| key | 설명 | value 타입 | 위치 | 제약사항 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- | --- |
| serviceResultId | 조회할 수행 결과 ID | UUID | Path Variable | - | X | `b2c3d4e5-1234-5678-9abc-def012345678` |

## Response

| key | 설명 | value 타입 | 옵션 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- |
| serviceResultId | 서비스 수행 결과 ID | UUID | - | X | `b2c3d4e5-1234-5678-9abc-def012345678` |
| serviceScheduleId | 서비스 일정 ID | UUID | - | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| startedAt | 서비스 시작 일시 | LocalDateTime | - | X | `2026-09-01T09:00:00` |
| finishedAt | 서비스 종료 일시 | LocalDateTime | - | X | `2026-09-01T10:00:00` |
| note | 비고 | String | - | O | `null` |

**Example**

```jsx
// 성공
{
   "success": true,
        "code": 200,
        "message": "서비스 수행 결과 상세 조회 성공",
        "data": {
   "serviceResultId": "b2c3d4e5-1234-5678-9abc-def012345678",
           "serviceScheduleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
           "startedAt": "2026-09-01T09:00:00",
           "finishedAt": "2026-09-01T10:00:00",
           "note": null
}
}

// 실패
{
   "success": false,
        "code": "AUTH_FORBIDDEN",
        "message": "요청 권한이 없습니다.",
        "details": {
   "reason": "요청 권한이 없습니다."
},
   "timestamp": "2026-08-27T10:00:00Z"
}
```

## Status

| status | ErrorCode | response content |
| --- | --- | --- |
| `200` | - | 서비스 수행 결과 상세 조회 성공 |
| `400` | `INVALID_PARAMETER` | `serviceResultId`가 UUID 형식이 아님 |
| `403` | `AUTH_FORBIDDEN` | 본인 소유가 아니거나, 존재하지 않는 수행 결과/일정이거나, 허용되지 않는 역할 |
