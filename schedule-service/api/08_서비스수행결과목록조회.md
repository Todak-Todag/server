# 08. 서비스 수행 결과 목록 조회

| 항목 | 내용 |
| --- | --- |
| Method | `GET` |
| URL | `/api/v1/service-results` |
| 사용자 | 퇴원예정자, 서비스 제공자 |
| 카테고리 | 검색 |
| 테이블명 | `p_care_plan_service_results` |

## 설명

퇴원 예정자 또는 서비스 제공자가 자신과 관련된 서비스 수행 결과 목록을 조회한다.

## 비즈니스 규칙

- 퇴원 예정자는 **자신이 받은** 서비스의 수행 결과만, 서비스 제공자는 **자신이 제공한** 서비스의 수행 결과만 조회할 수 있다.
- 접근 권한은 `@PreAuthorize("hasAnyRole('PATIENT', 'SERVICE_PROVIDER')")`로 제한한다.
- 정렬은 최신순/오래된순만 가능하다 (정렬 필드는 `p_care_plan_service_results.createdAt` 고정, 기본값 `createdAt,DESC`).
- 소유권 필터링은 레코드별 개별 검증이 아니라 01번에서 확정된 **ID 목록 기반 조회** 방식을 따른다.
  - **퇴원 예정자**: care-plan-service Internal API(`GET /internal/v1/service-preferences?patientId=`)로 담당하는 모든 `servicePreferenceId` 목록을 조회한다.
  - **서비스 제공자**: provider-service Internal API(`GET /internal/v1/service-offerings?providerId=`)로 담당하는 모든 `serviceOfferingId` 목록을 조회한다.
  - **소유 ID가 0건이면 DB를 조회하지 않고 즉시 빈 페이지를 반환한다.**

### 조인 방식

`p_care_plan_service_results`에는 `service_preference_id`/`service_offering_id` 컬럼이 없고 `service_schedule_id`만 있다. 따라서 조회한 ID 목록을 결과 테이블에 직접 걸 수 없고, **`p_service_schedules`와 `service_schedule_id`로 조인한 뒤 일정 테이블 쪽 컬럼에 `IN` 조건을 적용한다.**

```sql
SELECT r.*
  FROM p_care_plan_service_results r
  JOIN p_service_schedules s ON r.service_schedule_id = s.service_schedule_id
 WHERE s.service_preference_id IN (:servicePreferenceIds)   -- 또는 s.service_offering_id IN (:serviceOfferingIds)
   AND s.deleted_at IS NULL
   AND r.deleted_at IS NULL
```

두 테이블 모두 schedule-service 소유라 DB 조인이 MSA 원칙에 위배되지 않는다. 연관관계 매핑이 아닌 논리 FK이므로 QueryDSL에서 `on` 절로 직접 조인한다.

## Request

| key | 설명 | value 타입 | 위치 | 제약사항 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- | --- |
| page | 페이지 번호 | Integer | Query Parameter | `null`이거나 음수면 `0`으로 보정 | O | `0` |
| size | 페이지 크기 | Integer | Query Parameter | `10`, `30`, `50`만 가능하며 기본값은 `10`. 이 외의 값이 들어오면 `10`으로 자동 변경 | O | `10` |
| sort | 정렬 | String | Query Parameter | 방향만 파싱(`ASC`/`DESC`), 필드는 `createdAt` 고정. 기본값 `createdAt,DESC` | O | `createdAt,DESC` |

## Response

| key | 설명 | value 타입 | 옵션 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- |
| serviceResultId | 서비스 수행 결과 ID | UUID | - | X | `b2c3d4e5-1234-5678-9abc-def012345678` |
| startedAt | 시작 일시 | LocalDateTime | - | X | `2026-09-01T09:00:00` |
| finishedAt | 종료 일시 | LocalDateTime | - | X | `2026-09-01T10:00:00` |

> `serviceScheduleId`/`note`는 목록 응답에 포함하지 않는다 (09번 상세 조회에는 포함 — 01번과 같은 목록/상세 응답 분리 원칙).
>

## Status

| status | ErrorCode | response content |
| --- | --- | --- |
| `200` | - | 조회 성공 (없을 시 빈 배열 반환) |
| `403` | `AUTH_FORBIDDEN` | `PATIENT`/`SERVICE_PROVIDER` 이외의 역할로 요청한 경우 |
