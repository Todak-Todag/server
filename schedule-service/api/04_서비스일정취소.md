# 04. 서비스 일정 취소

| 항목 | 내용 |
| --- | --- |
| Method | `PATCH` |
| URL | `/api/v1/service-schedules/{serviceScheduleId}/cancel` |
| 사용자 | 퇴원예정자 |
| 카테고리 | 수정 |
| 테이블명 | `p_service_schedules` |

## 설명

퇴원 예정자가 예정된 서비스 일정을 취소한다.

## 비즈니스 규칙

- 일정 시작 **24시간 전까지**만 취소할 수 있다.
- 본인에게 배정된 서비스 일정만 취소할 수 있다.
- 요청자의 `userId`와 `role`은 `@AuthenticationPrincipal UserContext user`를 통해 확인한다.
- ✅ 확정 (03번 문서와 동일 패턴): 일정 취소 시 `servicePreferenceId`를 기준으로 **care-plan-service Internal API를 호출**하여, 해당 서비스 희망 일정이 속한 Care Plan의 `carePlanId`, `finishDate`, `patientId`를 조회한다. 조회한 `patientId`와 요청자의 `userId`를 대조하여 본인 소유 일정인지 검증한다.
    - schedule-service와 care-plan-service는 데이터 소유권이 분리되어 있으므로(MSA 컨벤션 — `코드_컨벤션.md` 2장 참고), DB 직접 조인이 아닌 `infrastructure/client/`의 Feign 클라이언트로 조회한다.
    - ✅ 확정 (2026-09-02): 이 API는 03번 문서(`schedule-service.md` 5.5절)에서 `carePlanId`, `finishDate`를 조회하던 것과 **동일한 care-plan-service Internal API**이며, `patientId`까지 포함해 3개 필드를 모두 반환하는 것으로 확정됐다.
    - ⚠️ 확인 필요 (미해소): 이 API의 실제 엔드포인트 URL/응답 스펙 자체는 아직 문서화되어 있지 않다. 반환 필드 3개(`carePlanId`/`finishDate`/`patientId`)가 확정된 것이며, 엔드포인트 자체 스펙은 care-plan-service 쪽 API 명세서 확인 필요.
- 취소 시 `status`는 `CANCELED`로 변경되고 `cancelReason`, `canceledAt`이 기록된다.
- 이미 완료되었거나 취소된 서비스는 `409 CONFLICT`를 반환한다.

## Request

| key | 설명 | value 타입 | 위치 | 제약사항 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- | --- |
| serviceScheduleId | 취소할 서비스 일정 ID | UUID | Path Variable | 존재하는 서비스 일정이어야 함 | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| cancelReason | 취소 사유 | String | Body | - | X | `개인 사정으로 취소합니다` |

> ✅ 확정 (2026-09-02): 요청자의 `userId`/`role`은 Request 표에 헤더로 명시하지 않고 `@AuthenticationPrincipal UserContext user`로 주입받는 것으로 통일한다 (팀 확인 완료 — 이전 버전에 있던 `X-User-Id`/`X-User-Role` 행 제거).
>

## Response

| key | 설명 | value 타입 | 옵션 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- |
| serviceScheduleId | 취소된 서비스 일정 ID | UUID | - | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| canceledAt | 취소 처리 일시 | LocalDateTime | - | X | `2026-08-27T10:00:00` |

**Example**

```jsx
// 성공
{
  "success": true,
  "code": 200,
  "message": "서비스 일정 취소 성공",
  "data": {
    "serviceScheduleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
    "canceledAt": "2026-08-27T10:00:00"
  }
}

// 실패
{
  "success": false,
  "code": "SERVICE_SCHEDULE_INVALID_STATUS_FOR_CANCEL",
  "message": "서비스 일정 취소 실패",
  "details": {
    "reason": "취소할 수 없는 상태의 서비스 일정입니다."
  },
  "timestamp": "2026-08-27T10:00:00Z"
}
```

## Status

| status | response content |
| --- | --- |
| `200` | 취소 성공 |
| `400` | Validation 실패 |
| `403` | 권한 오류 (본인 소유가 아니거나, 취소 가능 시간(24시간 전)이 지났거나, 존재하지 않는 서비스 일정) (✅ 확정, 2026-09-03: 리소스 존재 여부를 노출하지 않기 위해 404 대신 403(`AUTH_FORBIDDEN`)으로 통일) |
| `409` | 취소할 수 없는 상태(이미 완료/취소됨)의 서비스 |
