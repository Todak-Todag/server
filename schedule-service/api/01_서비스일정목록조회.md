# 01. 서비스 일정 목록 조회

| 항목 | 내용 |
|---|---|
| Method | `GET` |
| URL | `/api/v1/service-schedules` |
| 사용자 | 퇴원예정자, 서비스 제공자 |
| 카테고리 | 검색 |
| 테이블명 | `p_service_schedules` |

## 설명

퇴원 예정자 또는 서비스 제공자가 자신과 관련된 서비스 일정 목록을 조회한다.

## 비즈니스 규칙

- 퇴원 예정자는 **자신이 받은** 서비스 일정 목록만, 서비스 제공자는 **자신이 제공한** 서비스 일정 목록만 조회할 수 있다.
- 요청자의 `userId`와 `role`은 `@AuthenticationPrincipal UserContext user`를 통해 확인한다.
- 상태(`status`)와 날짜(`date`)로 필터링할 수 있다.
- 정렬은 최신순/오래된순이 가능하다 (기본값 `createdAt,DESC`).
- `status` 필터에 허용되지 않는 값이 들어오면 `400`을 반환한다 (✅ 확정, 2026-09-03).

### ✅ 확정 (2026-09-03): 소유권 필터링 방식 — ID 목록 기반 조회

목록 조회는 03/04/05번 API의 "레코드 하나가 내 것인지" 점(point) 검증 방식을 그대로 쓸 수 없다. 레코드 수만큼 Internal API를 개별 호출하면 (1) 요청당 네트워크 호출이 N번으로 늘어나고 (2) 필터링이 애플리케이션 레벨에서 끝난 뒤에야 가능해져 `size`/`page` 기반 페이지네이션이 DB 레벨에서 동작하지 않기 때문이다.

따라서 다음과 같이 **요청자가 소유한 ID 전체 목록을 한 번에 받아와서 `IN` 조건으로 필터링**하는 방식으로 확정한다.

- **퇴원 예정자가 조회하는 경우**: care-plan-service Internal API에 요청자 `userId`(patientId)를 전달하여, 해당 환자가 담당하는 모든 `servicePreferenceId` 목록을 조회한다.
- **서비스 제공자가 조회하는 경우**: provider-service Internal API에 요청자 `userId`(providerId)를 전달하여, 해당 제공자가 담당하는 모든 `serviceOfferingId` 목록을 조회한다.
- 조회한 ID 목록으로 `p_service_schedules WHERE service_preference_id IN (:ids)` 또는 `WHERE service_offering_id IN (:ids)` 조건을 적용하고, 여기에 `status`/`date` 필터와 페이지네이션(`page`/`size`/`sort`)을 함께 적용한다.
- Internal API 호출은 **요청당 1회**로 끝나며, DB 조회도 페이지네이션이 정상 동작하는 단일 쿼리로 처리된다.

### ✅ 확정 (2026-09-03): Internal API 스펙

| 대상 | Method/URL | Request | Response |
|---|---|---|---|
| care-plan-service | `GET /internal/v1/service-preferences?patientId={patientId}` | `patientId` (UUID, Query Parameter) | `data.content`: `servicePreferenceId` UUID 배열 |
| provider-service | `GET /internal/v1/service-offerings?providerId={providerId}` | `providerId` (UUID, Query Parameter) | `data.content`: `serviceOfferingId` UUID 배열 |

두 API 모두 응답은 `ApiResponse` 공통 포맷(`success`/`code`/`message`/`data`)을 따르며, `data.content`가 UUID 문자열 배열이다 (객체 배열이 아님에 유의 — 예: `["9b2f1c3a-...", "5d8a7e2b-..."]`).

## Request

| key | 설명 | value 타입 | 위치 | 제약사항 | Nullable | 예시 |
|---|---|---|---|---|---|---|
| page | 페이지 번호 | Integer | Query Parameter | 음수 불가능 | O | `0` |
| size | 페이지 크기 | Integer | Query Parameter | `10`, `30`, `50`만 가능하며 기본값은 `10`. 이 외의 값이 들어오면 `10`으로 자동 변경 | O | `10` |
| sort | 정렬 | String | Query Parameter | 최신순/오래된순 가능, 기본값 `createdAt,DESC` | O | `createdAt,DESC` |
| status | 상태 필터 | String(ENUM) | Query Parameter | `SCHEDULED`, `RESCHEDULING`, `CHANGED`, `COMPLETED`, `CANCELED`, `NO_SHOW`만 가능 | O | `SCHEDULED` |
| date | 날짜 필터 | Date | Query Parameter | - | O | `2026-09-01` |

## Response

| key | 설명 | value 타입 | 옵션 | Nullable | 예시 |
|---|---|---|---|---|---|
| serviceScheduleId | 서비스 일정 ID | UUID | - | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| status | 일정 상태 | String(ENUM) | `SCHEDULED`, `RESCHEDULING`, `CHANGED`, `COMPLETED`, `CANCELED`, `NO_SHOW` | X | `SCHEDULED` |
| date | 일정 날짜 | LocalDate | - | X | `2026-09-01` |
| startedAt | 시작 일시 | LocalDateTime | - | X | `2026-09-01T09:00:00` |
| finishedAt | 종료 일시 | LocalDateTime | - | X | `2026-09-01T10:00:00` |

## Status

| status | response content |
|---|---|
| `200` | 조회 성공 (없을 시 빈 배열 반환) |
| `400` | `status` 필터에 허용되지 않는 값이 들어온 경우 (✅ 확정, 2026-09-03) |
