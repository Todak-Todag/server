# 01. 서비스 일정 목록 조회

| 항목 | 내용 |
| --- | --- |
| Method | `GET` |
| URL | `/api/v1/service-schedules` |
| 사용자 | 퇴원예정자, 서비스 제공자 |
| 카테고리 | 검색 |
| 테이블명 | `p_service_schedules` |

## 설명

퇴원 예정자 또는 서비스 제공자가 자신과 관련된 서비스 일정 목록을 조회한다.

## 비즈니스 규칙

- 퇴원 예정자는 **자신이 받은** 서비스 일정 목록만, 서비스 제공자는 **자신이 제공한** 서비스 일정 목록만 조회할 수 있다.
- 접근 권한은 `@PreAuthorize("hasAnyRole('PATIENT', 'SERVICE_PROVIDER')")`로 제한하며, 요청자의 `userId`/`role`은 `@AuthenticationPrincipal UserContext user`로 주입받는다.
- 상태(`status`)와 날짜(`date`)로 필터링할 수 있다. `date`는 **정확히 일치하는 날짜**만 조회한다(범위 검색 아님).
- `status` 필터에 허용되지 않는 값이 들어오면 `400`을 반환한다. Spring 기본 Enum 컨버터를 쓰지 않고 `String`으로 받아 `ScheduleStatus.fromFilter()`에서 직접 파싱하며, 빈 문자열은 필터 미지정으로 처리한다.
- 정렬은 최신순/오래된순만 가능하다 (정렬 필드는 `createdAt` 고정, 기본값 `createdAt,DESC`).

### 소유권 필터링 — ID 목록 기반 조회

목록 조회는 02/03/04/05번의 "레코드 하나가 내 것인지" 점(point) 검증 방식을 쓰지 않는다. 레코드 수만큼 Internal API를 호출하면 (1) 요청당 네트워크 호출이 N번으로 늘어나고 (2) 필터링이 애플리케이션 레벨로 밀려 `page`/`size` 페이지네이션이 DB 레벨에서 동작하지 않기 때문이다.

- **퇴원 예정자**: care-plan-service Internal API에 요청자 `userId`(patientId)를 전달해 담당하는 모든 `servicePreferenceId` 목록을 조회한다.
- **서비스 제공자**: provider-service Internal API에 요청자 `userId`(providerId)를 전달해 담당하는 모든 `serviceOfferingId` 목록을 조회한다.
- 조회한 ID 목록으로 `WHERE service_preference_id IN (:ids)` 또는 `WHERE service_offering_id IN (:ids)` 조건을 적용하고, `status`/`date` 필터와 페이지네이션을 같은 쿼리에 함께 건다. 논리 삭제(`deleted_at IS NOT NULL`) 건은 제외한다.
- **소유 ID가 0건이면 DB를 조회하지 않고 즉시 빈 페이지를 반환한다.**
- Internal API 호출은 **요청당 1회**이며, Facade에서 DB 트랜잭션 밖으로 수행한다.

### Internal API 스펙

| 대상 | Method/URL | Request | Response |
| --- | --- | --- | --- |
| care-plan-service | `GET /internal/v1/service-preferences?patientId={patientId}` | `patientId` (UUID, Query Parameter) | `data.content`: `servicePreferenceId` UUID 배열 |
| provider-service | `GET /internal/v1/service-offerings?providerId={providerId}` | `providerId` (UUID, Query Parameter) | `data.content`: `serviceOfferingId` UUID 배열 |

두 API 모두 응답은 `ApiResponse` 공통 포맷(`success`/`code`/`message`/`data`)을 따르며, `data.content`가 UUID 문자열 배열이다 (객체 배열이 아님 — 예: `["9b2f1c3a-...", "5d8a7e2b-..."]`).

## Request

| key | 설명 | value 타입 | 위치 | 제약사항 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- | --- |
| page | 페이지 번호 | Integer | Query Parameter | `null`이거나 음수면 `0`으로 보정 | O | `0` |
| size | 페이지 크기 | Integer | Query Parameter | `10`, `30`, `50`만 가능하며 기본값은 `10`. 이 외의 값이 들어오면 `10`으로 자동 변경 | O | `10` |
| sort | 정렬 | String | Query Parameter | 방향만 파싱(`ASC`/`DESC`), 필드는 `createdAt` 고정. 기본값 `createdAt,DESC` | O | `createdAt,DESC` |
| status | 상태 필터 | String(ENUM) | Query Parameter | `SCHEDULED`, `RESCHEDULING`, `CHANGED`, `COMPLETED`, `CANCELED`, `NO_SHOW`만 가능 | O | `SCHEDULED` |
| date | 날짜 필터 | LocalDate | Query Parameter | `yyyy-MM-dd` | O | `2026-09-01` |

## Response

| key | 설명 | value 타입 | 옵션 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- |
| serviceScheduleId | 서비스 일정 ID | UUID | - | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| status | 일정 상태 | String(ENUM) | `SCHEDULED`, `RESCHEDULING`, `CHANGED`, `COMPLETED`, `CANCELED`, `NO_SHOW` | X | `SCHEDULED` |
| date | 일정 날짜 | LocalDate | - | X | `2026-09-01` |
| startedAt | 시작 일시 | LocalDateTime | - | X | `2026-09-01T09:00:00` |
| finishedAt | 종료 일시 | LocalDateTime | - | X | `2026-09-01T10:00:00` |

> 내부 필터링에만 쓰이는 `servicePreferenceId`/`serviceOfferingId`는 응답에 노출하지 않는다 (02번 상세 조회에는 포함 — 의도된 차이).

## Status

| status | ErrorCode | response content |
| --- | --- | --- |
| `200` | - | 조회 성공 (없을 시 빈 배열 반환) |
| `400` | `SERVICE_SCHEDULE_INVALID_STATUS_FILTER` | `status` 필터에 허용되지 않는 값이 들어온 경우 |
| `400` | `INVALID_PARAMETER` | `date` 형식 오류 등 파라미터 타입 오류 |
| `403` | `AUTH_FORBIDDEN` | `PATIENT`/`SERVICE_PROVIDER` 이외의 역할로 요청한 경우 |
