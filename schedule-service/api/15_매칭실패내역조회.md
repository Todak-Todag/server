# 15. 매칭 실패 내역 조회

| 항목 | 내용 |
| --- | --- |
| Method | `GET` |
| URL | `/api/v1/matching-attempts` |
| 사용자 | 퇴원예정자 |
| 카테고리 | 검색 |
| 테이블명 | `p_service_matching_attempts` |

## 설명

퇴원 예정자가 자신의 서비스 희망 일정에 대한 매칭 시도(성공/실패) 내역을 조회한다.

## 비즈니스 규칙

- 요청자의 `userId`와 `role`은 `@AuthenticationPrincipal UserContext user`를 통해 확인한다.
- care-plan-service Internal API(`GET /internal/v1/service-preferences?patientId=`)에 요청자 `userId`를 전달하여 담당하는 모든 `servicePreferenceId` 목록을 조회한 후, 해당 목록을 기준으로 매칭 시도 내역을 조회한다.
- 매칭 시도는 `ProviderMatched`/`ProviderMatchFailed` 이벤트를 수신할 때마다 새로운 이력으로 **누적(append)** 되며, 하나의 `servicePreferenceId`에 대해 여러 건의 시도 내역이 존재할 수 있다.
- 상태(`status`)로 필터링 가능하며, 별도 지정이 없으면 재매칭이 필요한 **`FAILED` 내역만 기본으로 조회**한다.
- 정렬은 최신순/오래된순 가능 (기본값 `createdAt,DESC`).

> 참고 : 이 API의 존재로 "초기 매칭 실패 시 결과를 어떻게 확인하는지"가 확정된다 — 사용자는 이 API로 실패 내역을 조회하고, 실패한 건에 대해 16번(재매칭 시도) API를 호출해 재시도한다.
>

## Request

| key | 설명 | value 타입 | 위치 | 제약사항 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- | --- |
| page | 페이지 번호 | Integer | Query Parameter | 음수 불가능 | O | `0` |
| size | 페이지 크기 | Integer | Query Parameter | `10`, `30`, `50`만 가능, 기본값 `10`. 이 외 값이면 `10`으로 자동 변경 | O | `10` |
| sort | 정렬 | String | Query Parameter | 최신순/오래된순, 기본값 `createdAt,DESC` | O | `createdAt,DESC` |
| status | 매칭 결과 필터 | String(ENUM) | Query Parameter | `MATCHED`, `FAILED`만 가능, 기본값 `FAILED` | O | `FAILED` |

## Response

| key | 설명 | value 타입 | 옵션 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- |
| matchingAttemptId | 매칭 시도 ID | UUID | - | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| servicePreferenceId | 서비스 희망 일정 ID | UUID | - | X | `3f2504e0-4f89-41d3-9a0c-0305e82c3301` |
| provideServiceId | 제공 서비스 ID | UUID | - | X | `94d8e2b6-3f71-4a95-c608-1e7b5d9f2a43` |
| date | 매칭을 시도한 희망 날짜 | LocalDate | - | X | `2026-09-01` |
| preferredTimeSlot | 매칭을 시도한 희망 시간대 | String(ENUM) | `MORNING`, `AFTERNOON` | O | `MORNING` |
| status | 매칭 시도 결과 | String(ENUM) | `MATCHED`, `FAILED` | X | `FAILED` |
| failureReason | 실패 사유 (`status`가 `FAILED`인 경우에만 존재) | String | - | O | `해당 날짜/시간대에 제공 가능한 서비스 제공자 없음` |
| failedAt | 매칭 실패 일시 | LocalDateTime | - | O | `2026-09-01T09:00:00` |
| matchedAt | 매칭 성공 일시 | LocalDateTime | - | O | `null` |

> 참고: `matchingAttemptId`가 응답에 포함되어, 실패 건에 대해 바로 16번(재매칭 시도) API의 Path Variable로 사용할 수 있는 구조다. 또한 `regionId`, `carePlanId`가 Response에 없는데, 이는 01번 문서에서 `servicePreferenceId`/`serviceOfferingId`를 응답에서 뺀 것과 같은 맥락(클라이언트에 불필요한 내부 참조 ID는 노출하지 않는 설계)으로 보인다.
>
