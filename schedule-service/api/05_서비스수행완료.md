# 05. 서비스 수행 완료

| 항목 | 내용 |
| --- | --- |
| Method | `PATCH` |
| URL | `/api/v1/service-schedules/{serviceScheduleId}/result` |
| 사용자 | 서비스 제공자 |
| 카테고리 | 수정 |
| 테이블명 | `p_service_schedules` |

## 설명

서비스 제공자가 자신이 배정된 서비스 일정의 수행을 완료 또는 미완료(예약 부도) 처리한다.

## 비즈니스 규칙

- 접근 권한은 `@PreAuthorize("hasRole('SERVICE_PROVIDER')")`로 제한하며, 요청자의 `userId`는 `@AuthenticationPrincipal UserContext user`로 주입받는다.
- 서비스 일정의 `status`가 `SCHEDULED`인 경우에만 변경 가능하다.
- 요청 시점이 해당 일정의 `finishedAt` **이후**여야만 변경 가능하다. 위반 시 **`400`** (`SERVICE_SCHEDULE_STATUS_UPDATE_TOO_EARLY`).
- 본인이 해당 일정에 배정된 서비스 제공자인지 검증하기 위해 **provider-service Internal API**(`GET /internal/v1/service-offerings/{serviceOfferingId}`)를 호출해 `providerId`를 조회하고 요청자 `userId`와 비교한다.
  - 응답 구조는 `data.providerId` — `providerId`가 `data`의 최상위 필드다.
  - schedule-service와 provider-service는 데이터 소유권이 분리되어 있으므로 DB 직접 조인이 아닌 `infrastructure/client/`의 Feign 클라이언트로 조회하며, 호출은 **DB 트랜잭션 밖**에서 수행한다.
  - `X-Internal-Api-Key` 헤더는 `FeignConfig`의 `RequestInterceptor`가 자동으로 붙인다.
- **검증 순서**: 배정 제공자 확인(403) → `finishedAt` 경과 확인(400) → 상태 전이(409).
- 이미 취소(`CANCELED`)/변경 중(`RESCHEDULING`)/변경 완료(`CHANGED`)/완료(`COMPLETED`)/부도(`NO_SHOW`)된 일정은 `409 CONFLICT`를 반환한다.
- 이 API로 상태가 `COMPLETED`/`NO_SHOW`가 되어야만 07번(수행 결과 등록)을 진행할 수 있다.

## Request

| key | 설명 | value 타입 | 위치 | 제약사항 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- | --- |
| serviceScheduleId | 수행을 완료할 서비스 일정 ID | UUID | Path Variable | 존재하는 서비스 일정이어야 함 | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| status | 수행 완료된 상태 | String(Enum) | Body | `@NotNull`, `COMPLETED` / `NO_SHOW`만 허용 | X | `COMPLETED` |

## Response

| key | 설명 | value 타입 | 옵션 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- |
| serviceScheduleId | 서비스 일정 ID | UUID | - | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| status | 일정 상태 | String(ENUM) | `COMPLETED`, `NO_SHOW` | X | `NO_SHOW` |

**Example**

```jsx
// 성공
{
  "success": true,
        "code": 200,
        "message": "서비스 수행 완료 상태 변경 성공",
        "data": {
  "serviceScheduleId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
          "status": "NO_SHOW"
}
}

// 실패
{
  "success": false,
        "code": "SERVICE_SCHEDULE_INVALID_STATUS_FOR_COMPLETED",
        "message": "완료할 수 없는 상태의 서비스 일정입니다.",
        "details": {
  "reason": "완료할 수 없는 상태의 서비스 일정입니다."
},
  "timestamp": "2026-08-27T10:00:00Z"
}
```

## Status

| status | ErrorCode | response content |
| --- | --- | --- |
| `200` | - | 수행 완료 처리 성공 |
| `400` | `SERVICE_SCHEDULE_STATUS_UPDATE_TOO_EARLY` | 일정의 `finishedAt` 이전에 요청 |
| `400` | `INVALID_PARAMETER` | `status` 누락 또는 `COMPLETED`/`NO_SHOW` 이외의 값 (Enum 역직렬화 실패 포함) |
| `403` | `AUTH_FORBIDDEN` | 본인이 배정된 서비스 제공자가 아니거나, 존재하지 않는 서비스 일정 (리소스 존재 여부 비노출) |
| `409` | `SERVICE_SCHEDULE_INVALID_STATUS_FOR_COMPLETED` | 완료 상태로 변경할 수 없는 서비스 (이미 취소/변경 중/변경완료/완료/부도) |
| `500` | `INTERNAL_SERVER_ERROR` | provider-service Internal API 호출 실패 (미존재 `serviceOfferingId`, 상대 서비스 장애 등) |

> ⚠️ **미해소**: Internal API 호출 실패에 대한 전용 예외 처리가 없어 `FeignException`이 그대로 전파되어 `500`으로 응답한다. 존재하지 않는 `serviceOfferingId`(상대 서비스 `404`)도 같은 경로다. 02·07·09번 등 Internal API를 호출하는 모든 API에 공통으로 해당한다.
