# 05. 서비스 수행 완료

| 항목 | 내용 |
| --- | --- |
| Method | `PATCH` |
| URL | `/api/v1/service-schedules/{serviceScheduleId}/result` |
| 사용자 | 서비스 제공자 |
| 카테고리 | 수정 |
| 테이블명 | `p_service_schedules` |

## 설명

서비스 제공자가 자신이 배정된 서비스 일정의 수행을 완료 또는 미완료(예약 부도) 처리한다.

## 비즈니스 규칙

- 서비스 일정의 `status`가 `SCHEDULED`인 경우에만 변경 가능하다.
- 요청 시점이 해당 일정의 `finishedAt` 이후여야만 변경 가능하다.
- 요청자의 `userId`와 `role`은 `@AuthenticationPrincipal UserContext user`를 통해 확인하며, 해당 서비스 일정에 배정된 서비스 제공자 본인인지와 서비스 제공자 권한을 검증한다.
    - 본인이 해당 서비스 일정에 배정된 서비스 제공자인지 검증하기 위해 **provider-service Internal API**(`GET /internal/v1/service-offerings/{serviceOfferingId}`)를 호출하여 해당 `serviceOfferingId`의 `providerId`를 조회하고, 조회된 `providerId`와 요청자의 `userId`를 비교하여 배정 여부를 검증한다.
    - schedule-service와 provider-service는 데이터 소유권이 분리되어 있으므로(MSA 컨벤션 — `코드_컨벤션.md` 2장 참고), DB 직접 조인이 아닌 `infrastructure/client/`의 Feign 클라이언트로 조회한다 (03/04번 문서의 care-plan-service Internal API 호출과 동일한 패턴).
    - Internal API 호출이므로 `X-Internal-Api-Key` 헤더 기반 인증을 따른다 (`코드_컨벤션.md` 15장 참고).
    - ⚠️ 확인 필요 (신규): 이 API의 정확한 Response 필드명(예: `providerId`가 응답의 루트 필드인지, 다른 객체 안에 중첩되어 있는지)과 존재하지 않는 `serviceOfferingId`일 때의 처리(에러 코드/상태)는 이번 문서에 명시되어 있지 않다.
- 이미 취소(`CANCELED`)되었거나 연기 중(`RESCHEDULING`)이거나 변경 완료(`CHANGED`)되었거나 이미 완료(`COMPLETED`/`NO_SHOW`)된 서비스는 `409 CONFLICT`를 반환한다.

## Request

| key | 설명 | value 타입 | 위치 | 제약사항 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- | --- |
| serviceScheduleId | 수행을 완료할 서비스 일정 ID | UUID | Path Variable | 존재하는 서비스 일정이어야 함 | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| status | 수행 완료된 상태 | String(Enum) | Body | `COMPLETED`, `NO_SHOW` | X | `COMPLETED` |

## Response

| key | 설명 | value 타입 | 옵션 | Nullable | 예시 |
| --- | --- | --- | --- | --- | --- |
| serviceScheduleId | 서비스 일정 ID | UUID | - | X | `3fa85f64-5717-4562-b3fc-2c963f66afa6` |
| status | 일정 상태 | String(ENUM) | `COMPLETED`, `NO_SHOW` | X | `NO_SHOW` |

```jsx
// 성공
{

  "message": "서비스 수행 완료 상태 변경 성공",
  "data": {

  }
}

// 실패
{
  "success": false,
  "code": "SERVICE_SCHEDULE_INVALID_STATUS_FOR_COMPLETED",
  "message": "서비스 수행 완료 실패",
  "details": {

  },
  "timestamp": "2026-08-27T10:00:00Z"
}
```

## Status

| status | response content |
| --- | --- |
| `200` | 수행 완료 처리 성공 |
| `403` | 권한 오류 — 본인이 배정된 서비스 제공자가 아니거나, `finishedAt` 이전 요청이거나, 존재하지 않는 서비스 일정인 경우 (리소스 존재 여부 비노출, 03/04번과 동일 정책) |
| `409` | 완료 상태로 변경할 수 없는 서비스 (이미 취소/연기/변경완료/완료/부도) |

> ⚠️ 확인 필요 (신규): Request의 `status` 필드는 `COMPLETED`/`NO_SHOW` 둘 중 하나만 허용되는데, Status 표에 이 값이 아닌 다른 문자열이 오거나 필드가 누락됐을 때의 **400 Validation 실패 케이스가 없다**. 다른 API 문서(01~04번)는 대부분 Validation 실패에 대해 `400`을 명시하고 있어, 이 문서만 빠진 것인지 실제로 이 API는 400을 반환하지 않고 다른 방식(예: 항상 403/404로 흡수)으로 처리하는지 확인 필요.
>
